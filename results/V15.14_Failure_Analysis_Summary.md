## Root Cause Analysis: The 24 Failures Categorized

### Priority 2: False Positives on Non-Mandated Flows (7 failures, +5-7 fixes, LOW RISK)

**Root Cause:** Pipeline extracts values mentioned in documents that are NOT mandated minimum flows:
- **Observed statistics** (Dry Spruce: 0.35 cfs "low flow value")
- **Processing/Municipal use** (Chignik: 1.3 cfs seafood processing)
- **Monitoring thresholds** (Bradley: 497 cfs monitoring provision)
- **Study/Consultation flows** (Martin: 400 cfs, Lake Dorothy: 40 cfs)
- **Temporary construction flows** (Abiquiu: 50 cfs during construction only)
- **Hatchery supply** (Blind Slough: 12.5 cfs max supply vs 8.2 cfs base operational)
- **Misidentified operations** (Tyee: 200 cfs operational value, not mandated minimum)

**Current Logic Gap:** Pattern detection for `detect_zero_flow_capability()` and Article extraction doesn't distinguish between:
- "Mandated continuous minimum flow" (REQUIRED)
- "Observed streamflow statistics" (DATA ONLY)
- "Flow for [municipal/processing] use" (WITHDRAWAL, not environmental minimum)
- "Monitoring/consultation provision" (CONDITIONAL STUDY)
- "During construction" (TEMPORARY)

**Proposed Fix (V15.15):**
```python
NOT_MINIMUM_PATTERNS = [
    # Observed data, not requirements
    r'streamflow statistics',
    r'observed flow',
    r'low flow value in',
    r'hydrologic.*(?:data|record)',
    
    # Non-environmental uses
    r'for seafood processing',
    r'municipal water supply',
    r'domestic water',
    r'hatchery',
    r'fish processing',
    
    # Studies and conditional measures
    r'consultation',
    r'monitoring',
    r'adaptive management',
    r'study',
    r'report',
    r'prepare a plan',
    r'if issues? (?:are )?detected',
    r'recommend',
    
    # Temporary/construction
    r'during construction',
    r'temporary',
    r'construction period',
    
    # Explicit statements of no requirement
    r'does not have a minimum flow',
    r'no minimum flow requirement',
    r'no (?:reservoir )?operational restrictions?',
]

# In V13_HYBRID logic, after extracting flow value:
if has_not_minimum_context(chunk, NOT_MINIMUM_PATTERNS):
    continue  # Skip this value, it's not a mandated minimum
```

**Expected Improvement:** +5-7 correct (Dry Spruce, Chignik, Bradley, Tyee, Martin, Lake Dorothy, Abiquiu, possibly Blind Slough)

**Risk:** **LOW** - Only filters out values with explicit non-requirement context. Won't affect properly mandated Article requirements.

### Priority 3: Seasonal/Multi-tier Wrong Selection (8 failures, +3-5 fixes, MEDIUM RISK)

**Root Cause:** When documents contain multiple seasonal tiers or multi-reach requirements, pipeline picks wrong value:

**Type 3a: Seasonal Schedule - Picked Lower Season** (4 failures):
- Blue Lake: Picked 22 cfs (unrelated) vs seasonal 70/50 cfs
- City of Hamilton: Picked 250 cfs (summer) vs 400 cfs (spring spawning)
- Wallowa Falls: Picked 5 cfs (May-Oct) vs 4 cfs (Nov-Apr) absolute minimum
- Whitman Lake: Picked 2 cfs (diversion dam) vs 6-11 cfs (lower creek)

**Type 3b: Multi-reach - Picked Lower Priority Reach** (2 failures):
- Reynolds Creek: Picked 10 cfs (bypassed reach) vs 12 cfs (anadromous reach)
- Catawba-Wateree: Picked 325 cfs (wrong development) vs 95 cfs (Bridgewater minimum)

**Type 3c: Wrong Value from Range/Schedule** (2 failures):
- Cooper Lake: Picked 150 cfs (unrelated) vs 10-30 cfs variable minimum (should be 10)
- Terror Lake: Picked 0 cfs (error) vs seasonal schedule 62-100 cfs (minimum = 62)

**Current Logic Gap:** V13_HYBRID selects "lowest value" from candidates, but doesn't account for:
1. **User Intent:** "Absolute minimum" means lowest across ALL seasons/conditions, not just what's mentioned first
2. **Biological Priority:** Anadromous/fish passage reaches > bypassed reaches
3. **Seasonal Priority:** Should select absolute lowest seasonal value when asked for "absolute minimum"

**Proposed Fix (V15.15):**

**For User Query "Absolute Minimum":**
```python
# When extracting from seasonal schedule:
if has_seasonal_schedule:
    # Extract ALL seasonal values, return absolute minimum
    all_seasonal_values = extract_all_from_schedule(article_text)
    return min(all_seasonal_values)

# Multi-reach priority:
REACH_PRIORITY = [
    'anadromous',
    'fish passage',
    'spawning',
    'lower creek',
    'bypassed reach',
    'diversion'
]

if multiple_reaches_detected:
    # Select reach with highest biological priority
    prioritized_value = select_by_reach_priority(values, REACH_PRIORITY)
```

**Expected Improvement:** +3-5 correct (Hamilton, Reynolds, Wallowa, possibly Blue Lake, Cooper, Terror, Catawba-Wateree)

**Risk:** **MEDIUM** - Could affect currently correct seasonal extractions if not implemented carefully. Need to ensure we're still extracting from correct Article/context.

### Priority 4: Ottumwa Prior License Filter (1 failure, +1 fix, ZERO RISK)

**Root Cause:** Extracted 300 cfs from **prior license** when **new license** explicitly states this requirement was NOT continued.

**Document Context:**
- Prior license (1980s): Required 300 cfs minimum
- New license (2008): "Prior license required a 300 cfs minimum, but this is **not continued in the new license**"
- New requirement: Run-of-river only (outflow = inflow), no numeric minimum

**Current Logic Gap:** Pipeline doesn't distinguish temporal context (prior vs current license).

**Proposed Fix (V15.15):**
```python
PRIOR_LICENSE_PATTERNS = [
    r'prior license required.*?(\d+\.?\d*)\s*cfs',
    r'previous license.*?(\d+\.?\d*)\s*cfs',
    r'former license.*?(\d+\.?\d*)\s*cfs',
]

NOT_CONTINUED_PATTERNS = [
    r'not continued',
    r'not carried forward',
    r'is not (?:included|required) in (?:the )?(?:new|this) license',
    r'superseded',
]

# When extracting flow value:
if matches_prior_license(chunk) and matches_not_continued(chunk):
    return "No minimum flow required"  # Prior requirement was removed
```

**Expected Improvement:** +1 correct (Ottumwa)

**Risk:** **ZERO** - Only triggers when both "prior license required X" AND "not continued" appear together. Very specific pattern.
