Error classification on three primary error categories showed that false positive extraction was most prevalent (6 cases, 50.0%), where the model extracted values when documents explicitly stated "no minimum flow required" or didn't mention minimum flows at all (e.g., P12379 extracted "40 cfs" when document stated "no minimum flow required"). This was followed by wrong numeric value extraction (4 cases, 33.3%) where documents contained specific minimum flow requirements but the model extracted incorrect values, with errors ranging from 60% deviation (P10813: 100 cfs → 160 cfs) to 2800% deviation (FortPeck: 3000 cfs → 85,000 cfs), and also included cases where the model extracted completely wrong numbers that didn't match any values in the document (P1773: document specified "35 cfs April-Sept, 20 cfs Oct-Mar" but model extracted "10 cfs"). Other errors accounted for the remaining cases (2 cases, 16.7%), including generation-based requirements incorrectly converted to flow values (LaurelRiver: "0.5 hr generation" → "60-70 cfs") and extraction of wrong flow types (P2566: extracted fishway flow instead of minimum flow requirement). The analysis covered 12 total errors from 50 documents, representing a 24% error rate. Most failures (50%) involved over-extraction bias where the model extracted values that don't exist, suggesting the model errs on the side of providing answers rather than acknowledging absence of information.
